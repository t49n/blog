WindowsからWSL2へドラッグ＆ドロップした直後にWSL2が起動しなくなった話と復旧手順

2026-10-05

WindowsエクスプローラーからWSL2（Ubuntu）のディレクトリへ画像をドラッグ＆ドロップした際、突然WSL2が起動しなくなる不具合に見舞われました。

ネット上に類似の症例が見当たらず解決に苦戦したため、実際に試行錯誤した復旧手順と、その後気をつけていることを記録として残します。

結論: Windows 11のISOファイルを使ったインプレース修復を行った後、wsl --uninstall と wsl --install でWSLを入れ直したところ復旧しました。Ubuntu内のデータも消えずに残っていました。

何が起きたか

WSL2上のプロジェクトディレクトリに、Windowsのエクスプローラーから画像ファイルをドラッグ＆ドロップで配置しました。

その直後からWSL2が完全に起動しなくなり、開発環境（Ubuntu）にアクセスできない状態になりました。

起動しようとすると「ファイルが見つかりません」といった趣旨のエラーが表示されていたはずですが、数か月前のことで正確な文言は覚えていません。WindowsやWSLのバージョンも控えていませんでした。

試した手順

1. Windowsの機能のオン/オフ切り替え

実施内容: 「Windowsの機能の有効化または無効化」から「Linux用Windowsサブシステム」と「仮想マシンプラットフォーム」をオフにし、再起動後に再びオン。

結果: 処理が進まなくなり、復旧せず。

機能の切り替えすら終わらないことをGeminiに相談したところ、Windows自体が壊れているかもしれないと言われたため、ここからはWindows本体の修復を試しました。

2. sfc /scannow によるシステム修復

実施内容: Windowsのシステムファイルが破損していないかを検査し、壊れていれば正常なコピーで置き換えるコマンド sfc /scannow（System File Checker）を、管理者権限で実行。

結果: 処理自体は正常に完了したものの、WSL2は起動せず。

3. DISMによるイメージ修復

実施内容: Windowsのシステムイメージを管理・修復するツールDISM（Deployment Image Servicing and Management）で、SFCが修復に使う元データ（コンポーネントストア）をWindows Updateなどから取得したファイルで修復するコマンド dism /online /cleanup-image /restorehealth を実行。

結果: 「修復ソースが見つかりませんでした」というエラーで失敗。

4. Windows 11のインプレース修復

実施内容: DISMの修復ソース不足を補うため、Microsoft公式サイトからWindows 11のISOファイルをダウンロードし、ISO内の setup.exe を実行。個人用ファイルとアプリを引き継ぐ設定で、現在のWindowsの上からWindowsを上書きインストール（インプレース修復）。

結果: インプレース修復が完了。

5. WSLの再インストール

実施内容: WSL本体のパッケージをアンインストールするコマンド wsl --uninstall を実行した後、wsl --install で改めてWSLをインストール。

結果: WSL2が正常に起動し、開発環境が復旧。Ubuntu内のデータも残っていた。

なお、インプレース修復が本当に必要だったのか、WSLの入れ直しだけで直ったのかは確認できていません。インプレース修復は時間のかかる作業なので、同じ症状の方はまず手順5の wsl --uninstall から試してみてもよいかもしれません。

その後気をつけていること

原因ははっきりしていませんが、念のため、WindowsとWSL2の間でファイルを受け渡すときはエクスプローラーでのドラッグ＆ドロップを避け、コマンドで操作するようにしています。

たとえば、Windows側の画像をWSL2へコピーする場合は次のようにします。

cp /mnt/c/Users/username/Pictures/sample.png ./
